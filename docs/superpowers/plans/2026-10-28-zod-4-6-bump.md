**Goal:** Take the fix for GHSA-mrhx-c7xc-m3w5 (zod `<4.6.6`) without losing the #769 bounds audit or the locale guard.

**Architecture:** The #769 audit in `src/lib/schemas.test.ts` reads each bound from `schema._zod.bag`, which zod 4.6 leaves `{}`. ## Review Focus

- A fixed-length array (`.length(n)`) must read as bounded — `length_equals`, not only `max_length`. Pinned in Task 1 step 1.
- A regex string with several `.regex()` checks is bounded only if *every* pattern is fixed-shape, as today. Pinned in Task 1 step 1.
- A string format with a `.max()` on top (`z.email().max(254)`) stays bounded through `.maxLength`. Covered by the export sweep.
- `.int()`'s safe-integer range must not count as a product bound — `SAFE_INT_LIMIT` comparison carries over to `.minValue`/`.maxValue`. Pinned by the existing `intNeither`/`intPositiveOnly` probes.
- The locale test must still fail if `register()` stops installing the locale. Proven by mutation in Task 2.

### Task 1: The #769 audit reads bounds without `_zod.bag` (on zod 4.4.3)

**Files:**

**Interfaces:**
- Produces: `numberBounds(schema)` and `walkLeaves(path, schema, out)` keep their signatures; the probe tests' expected offender lists are unchanged except for the additions in step 1.

- [ ] **Step 1: Extend the positive controls**

In `fails an array with no max and a type it does not know`, add `fixed: z.array(z.uuid()).length(2)` to the probe object; the expected list stays `['probe.a: array with no max', 'probe.r: unknown def type record']`.
Add one test, `reads a string's bound from its max, its length, a bounded format or every regex being fixed-shape`:

```ts
const out = emptyWalk();
walkLeaves('probe', z.object({
  max: singleLineText(5),
  len: singleLineCharacters(z.string(), 5).length(5),
  uuid: z.uuid(),
  fixed: singleLineCharacters(z.string(), 10).regex(/^\d{4}$/u).regex(/^[0-9]{4}$/u),
  open: singleLineCharacters(z.string(), 10).regex(/^\d{4}$/u).regex(/^\d+$/u),
  email: z.email(),
}), out);
```

Expect `[...out.unboundedStrings].sort()` to equal `['probe.email', 'probe.open']`, and `out.acceptsHidden` to equal `[]`. `singleLineCharacters` (`src/lib/input-bounds.ts`) adds only the character refine, no max, so `fixed` is bounded by its patterns alone and `open` by nothing.

- [ ] **Step 2: Run on 4.4.3** — `pnpm exec vitest run src/lib/schemas.test.ts`. Expected: PASS (the old bag reading already handles these). This shows the new controls are valid before the reader changes.

- [ ] **Step 3: Rewrite the reading**

- Strings: `maxLength` from the schema's `.maxLength` (non-null = bounded), `format` from `.format`. Access via a narrow local type (`schema as unknown as { maxLength: number | null; format: string | null }`) — strings are dispatched by `def.type`, not `instanceof z.ZodString`, because `z.uuid()` does not extend it; keep that dispatch and its comment.
- Regex patterns: every `string_format` check's `_zod.def.pattern` from `schema._zod.def.checks ?? []` — bounded when `.format === 'regex'` and every collected pattern is `isFixedShape`. This matches the bag on every `z.string()`-rooted leaf. It differs on a top-level format with a regex on top (`z.email().regex(fixed)`): the format is the schema, not a check, so its own pattern is not collected and the leaf reads bounded. That is correct, because every pattern must match. No exported schema has that shape.
- Arrays: bounded when some check's def is `max_length` or `length_equals`.
- Numbers: `numberBounds` reads `schema.minValue`/`schema.maxValue` (`z.ZodNumber`; dispatch stays by `def.type`, so narrow as for strings). `upper = maxValue !== null && maxValue < SAFE_INT_LIMIT`, `lower` mirrored. Exclusive bounds are already folded into the accessors (table above), so the `exclusive*` fields go.
- One small helper for "the check defs of a schema" if both arrays and regex use it; no helper for a single use.
- Update `SAFE_INT_LIMIT`'s docblock: `.int()` seeds `.minValue`/`.maxValue` with the safe-integer range, not "the bag".

- [ ] **Step 4: Run on 4.4.3** — same command. Expected: PASS, every test in the file.

- [ ] **Step 5: Prove each control bites** (record the exact failure text for the PR body, restore, re-run green after each):
  1. Array: make the array reader accept only `max_length` → `fails an array…` fails, `probe.fixed: array with no max` appears.
  2. Regex: make the pattern test `some` instead of `every` → the new string test fails, `probe.open` missing from `unboundedStrings`.
  3. String max: ignore `.maxLength` → the export sweep (`finds no unbounded leaf…`) fails with `string with no max` findings.
  4. Number: drop the `SAFE_INT_LIMIT` comparison → the number probe fails (`intNeither` no longer listed).

- [ ] **Step 6: Confirm** `grep -n "_zod.bag" src/lib/schemas.test.ts` → no hits; `pnpm exec tsc --noEmit -p .` and `pnpm exec eslint src/lib/schemas.test.ts` clean.

- [ ] **Step 7: Commit** — `git add src/lib/schemas.test.ts`; message `test: the #769 bounds audit reads public accessors and check defs, not _zod.bag (#928)`.
