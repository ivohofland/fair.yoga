> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `typescript` moves from 5.9.3 to an exact `6.0.3`. This is #944's final step; its prep (#945) is merged.

**Architecture:** A dependency bump plus the two edits that 6.0 makes possible or necessary. No source behaviour changes. The design was agreed in conversation (small change, no spec).

**Tech Stack:** pnpm (`minimumReleaseAge: 10080`, `--frozen-lockfile` in CI), TypeScript, Next.js 16.4.1, typescript-eslint 8.58.0.

**Spec:** none (small change, agreed at the brainstorming gate). The tracking issue is #944.

## Global Constraints

- `package.json` reads `"typescript": "6.0.3"`: exact, like the other toolchain pins (`next`, `prisma`, `@prisma/client`, `react`). Agreed at the gate.
- No new `@ts-expect-error`, and no change to `strict` or any other compiler option except removing `dom.iterable` from `lib`
- Install only with pnpm, so the lockfile passes `pnpm run check-lockfile`

## Measured before planning (2026-10-30, clean worktree at 4b1d14fb, no `next-env.d.ts` and no `.next-build/`)

- `tsc` 6.0.3, run read-only from the scratchpad: 0 errors, and also 0 with `--stableTypeOrdering`
- `lib` without `dom.iterable`: 6.0.3 gives 0 errors and 5.9.3 gives 5. In 6.0, `lib.dom.iterable.d.ts` contains only the license header and "This file's contents are now included in the main types file."
- `src/lib/type-pins.ts`'s `NoneOf` bracketing claim, re-measured with a throwaway fixture: identical on 5.9.3 and 6.0.3. Unbracketed, only the `never` (passing) case fails, with TS2322. Both forms reject one and two offenders.
- Every `typescript` peer range in the lockfile accepts 6.0.3. The tightest is typescript-eslint 8.58.0's `>=4.8.4 <6.1.0`.
- Next's `writeConfigurationDefaults` treats `lib` as a suggestion, applied only when the key is absent, so trimming the list is not rewritten
- 6.0.3 was published 2026-04-16, so it is past `minimumReleaseAge`

## Review Focus

1. **Typed lint on 6.0:** typescript-eslint parses with the installed compiler. It prints an "unsupported TypeScript version" warning if 6.0.3 falls outside its supported range. Step 4 reads the lint output for that warning, not just the exit code.
2. **`next build` on 6.0:** Next runs its own TypeScript pass and may rewrite `tsconfig.json`. Step 5 checks the exit code and `git diff --exit-code tsconfig.json`.
3. **Peer-dependency warnings at install:** Step 1 reads `pnpm install`'s output for `unmet peer` lines naming typescript.
4. **Docker image build:** CI's `docker-build` installs from the lockfile. Covered by CI only.
